# Threat Model

Описание системы: HTTP‑сервис, SQLite (in‑memory), файловая песочница, исполнитель решений ассистента, LLM‑судья. Акторы: покупатель, злоумышленник‑покупатель, оператор (staff), файловая система, LLM‑судья.

Активы и данные: профили (ПДн), заказы, файлы чеков, служебная записка, журналы запросов, токены сессий.

DFD: см. threat-model.mmd.

STRIDE+LLM таблица (кратко):
- T‑01 Spoofing/IDOR: доступ к /profile по id → утечка ПДн. Меры: скоуп по сессии, параметризация.
- T‑02 Tampering/Business logic: override price в /orders. Меры: цена из каталога.
- T‑03 Information Disclosure: /debug/logs открыт. Меры: staff‑only.
- T‑04 Repudiation: логи маскировать ПДн (в учебной версии — ограничение доступа).
- T‑05 DoS/Cost: не применять в учебной среде (лимит Body уже есть).
- T‑06 LLM Injection/Excessive Agency: /assistant/execute выполняет опасные инструменты. Меры: allow‑list и проверки прав.
- T‑07 Files/Path traversal: /files читает произвольные пути. Меры: фиксированный путь собственного чека.

Соответствие 152‑ФЗ (учебно): минимизация ПДн в ответах, доступ только владельцу, не отправлять ПДн в LLM без нужды, маскирование в логах (в учебной постановке — ограничение доступа).

Остаточные риски и допущения: отсутствие онлайн LLM‑прогона; песочница ограничивает физическую границу; тесты покрывают основные потоки.
