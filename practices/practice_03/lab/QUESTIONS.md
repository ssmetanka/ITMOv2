## 1. Конфигурация локального рантайма и моделей

Для изоляции процесса выполнения и автономной работы без сторонних облачных API был развернут локальный сервис Ollama.

С использованием `Modelfile` и `Modelfile.agent` были собраны два целевых образа:
* **`lab-qwen`**: базовая модель для прямых ответов (`num_ctx 4096`, `temperature 0.7`, `repeat_penalty 1.15`, `num_predict 512`). Параметр `repeat_penalty` был выставлен для предотвращения зацикливания цепочки рассуждений (repetition loop), возникавшего при жадном семплировании.
* **`lab-agent`**: специализированный образ для интеграции с OpenCode, поддерживающий расширенный системный контекст для передачи описания инструментов.

Системный промпт агента (`repo-system.txt`) определяет рамки выполнения:
1. Запрет на генерацию неподтверждённых гипотез (галлюцинаций).
2. Обязательный вызов инструмента чтения файлов (`Read`) перед формированием утверждений о проекте.
3. Прямая идентификация и опровержение ложных предпосылок в вопросах пользователя.
4. Выдача регламентированного ответа «В предоставленных материалах нет ответа» при отсутствии информации.
5. Изоляция агента от хостовой системы (отсутствие доступа к системному времени, ОС и сети).

## 2. Результаты экспериментов инференса (experiment.py)

Был произведён запуск `experiment.py` для сравнительного анализа времени обработки и генерации при фиксированном seed (42) и температуре (0.7).

### Сводная таблица параметров инференса

| Параметр | Baseline (`baseline.json`) | System (`system.json`) |
| :--- | :--- | :--- |
| **Входной запрос** | Вопрос о CI-системе проекта | Вопрос о CI-системе проекта |
| **Системный промпт** | Отсутствует | Включён (ограничение контекста) |
| **Prompt Eval Count (токены входа)** | 158 токенов | 167 токенов |
| **Prompt Eval Duration (Prefill)** | 61.9 мс | 41.2 мс |
| **Eval Count (сгенерировано токенов)** | 22 токена | 118 токенов |
| **Eval Duration (Decode)** | 904.4 мс | 5484.6 мс |
| **Скорость Decode** | 24.32 токена/сек | 21.51 токена/сек |
| **Общее время (Total Duration)** | **0.986 с** | **5.544 с** |
| **Результат генерации** | Корректный отказ: «В предоставленных материалах нет ответа» | Галлюцинация о GitLab и менеджерах пакетов |

### Анализ результатов:
1. **Фаза Prefill и кэширование:** На этапе обработки входа время `prompt_eval_duration` составило около 40–60 мс благодаря механизму KV-кэширования повторяющихся токенов описания проекта (`prompt_eval_cached_count` составил 154 и 163 токена соответственно).
2. **Фаза Decode:** Скорость пошаговой генерации токенов на CPU стабильна и составляет ~21–24 токена/сек. Основная разница в общем времени выполнения (0.98 с против 5.54 с) вызвана исключительно длиной ответа (22 токена против 118 токенов).
3. **Отказ от галлюцинаций в baseline:** В базовом режиме модель мгновенно остановилась на коротком ответе об отсутствии данных. Во втором случае модель попыталась дать развёрнутое обоснование, что привело к генерации ложных фактов о GitLab, не присутствующих в контексте.

## 3. Верификация агентных сценариев в OpenCode (5 проверок)

В среде OpenCode был запущен локальный агент `local-guide` со строгим разграничением прав (`read: allow`, `edit: deny`, `bash: deny`).

### Сценарий 1. Факт, зафиксированный в документации (README.md)
* **Вопрос:** «Где именно хранятся подписчики сервиса согласно README.md и что происходит при повторной попытке добавить существующее имя? Приведи цитату из документации на русском языке.»
* **Вызовы инструментов:** `Glob "**/README.md"`, `Read README.md`
* **Время ответа:** 2 мин 7 сек (с учётом первичного чтения файлов и рассуждений)
* **Фактический ответ агента:**
  > Согласно пункту 4 из README.md: «Повторительная попытка работы без ошибки или исключения, но результат будет тот же»... Сервис использует Set вместо обычного набора данных... Список уникальных имен хранится в памяти процесса через множество.
* **Оценка:** Успешно. Агент нашёл и прочитал `README.md`, подтвердил цитатой хранение в памяти и отсутствие дубликатов.

### Сценарий 2. Логика и поведение кода (service.py)

* **Оценка:** Успешно. Агент изучил исходный код `service.py`, локализовал возврат значения и указал точный номер строки.

## 4. Ответы на контрольные вопросы

1. **Разница между моделью, рантаймом и агентом:**
   * *Модель* — матрица обученных весов (Qwen 3.5 4B), предсказывающая распределение вероятностей следующего токена.
   * *Рантайм* (Ollama) — движок исполнения инференса, управляющий загрузкой весов в память, квантизацией, KV-кэшем и обработкой HTTP/API-запросов.
   * *Агент* (OpenCode `local-guide`) — управляющий контур, дополняющий модель системным промптом, историей диалога и внешними инструментами (tools: `read`).
2. **Prefill vs Decode:**
   * *Prefill* параллельно обрабатывает весь входной промпт и формирует KV-кэш (время до первого токена — TTFT).
   * *Decode* генерирует ответ строго последовательно, по одному токену за шаг, упираясь в пропускную способность памяти хоста.
3. **Безопасность агентного контура:**
   * Ограничение прав в `opencode.json` (`read: allow`, `edit: deny`, `bash: deny`) гарантирует, что даже при попытке Prompt Injection модель не сможет нанести ущерб файловой системе или выполнить произвольные shell-команды на хосте.
