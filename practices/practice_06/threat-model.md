# Threat Model: Mini Shop

Система: HTTP‑сервис, SQLite (in‑memory), файловая песочница, AI Assistant (планировщик), Tool Executor, журналы. Акторы: покупатель, злоумышленник‑покупатель, оператор (staff), файловая система. LLM‑судья — офлайн промпт, онлайн вызов не подтверждён.

Активы и данные: профили (ПДн), заказы, файлы чеков, служебная записка, журналы запросов, токены сессий.

DFD: см. threat-model.mmd. Границы доверия: клиент→HTTP API; API→SQLite; API→Sandbox; API→Logs; API→Planner/Judge (локально, без внешних отправок).

Угрозы и меры:
- T‑01 IDOR/SQLi в /profile и /assistant/context. Меры: серверная сессия, скоуп владельца, параметризованные SQL, 404 без раскрытия чужих заказов.
- T‑02 Tampering: подмена цены в /orders. Мера: цена только из каталога.
- T‑03 Disclosure: /debug/logs и логи содержат секреты. Меры: staff‑only и маскирование паролей, токенов, авторизации, query.
- T‑04 Dangerous actions: delete_tree. Мера: инструмент отключён.
- T‑05 Schema/AI: слабая валидация /assistant/execute. Меры: жёсткий allow‑list инструментов, типы и обязательные аргументы, запрет неизвестных полей, обработка malformed JSON.
- T‑06 XSS: хранимая XSS через отзывы. Меры: html.escape при рендере, авторизация и длина.
- T‑07 Files: Path Traversal. Меры: Sandbox.path, запрет чтения чужих чеков.
- T‑08 Errors: раскрытие внутренних деталей. Мера: унифицированный 500 + request_id, детали только в безопасных логах.

Недоверенные данные: текст отзывов, любые входные query/body, решения ассистента, заголовки клиента.

Остаточные риски: отсутствие rate‑limit, in‑memory логи, офлайн судья без онлайн исполнения, нагрузочные DoS не рассматриваются.
