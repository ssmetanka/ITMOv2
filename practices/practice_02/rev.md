# Ревью экспериментов Практики 2

## Общее соответствие требованиям (см. practices/practice_02/prompts.md)
- Журнал экспериментов (таблица) частично не заполнен: отсутствуют поля «Изменённый файл Практики 1», «Конкретное изменение», «Проверка», «Что отклонили» для всех техник.
- Блок «Независимое ревью» не заполнен (Двусмысленность, Непроверяемое требование, Пропущенный риск или источник).

## По файлам experiments

### 1) rag/experiment.md
Сильные стороны
- Сформирован корректный <context> с официальными источниками (FastAPI Request/Response Models, RFC 9110 422/502/504, PEP 585, OWASP LLM01, OWASP API4) и прямыми ссылками.
- Жёсткие правила grounding, запрет галлюцинаций соблюдён.
- Артефакт: риски привязаны к строкам diff и к нормам из контекста; присутствуют Repro и Mitigation.

Замечания
- Смешение языков (англ/рус) в Summary и тексте; лучше унифицировать.
- Нет явного раздела «Что отклонили как неподтверждённое».

### 2) rctf/experiment.md
Сильные стороны
- Полный RCTF: Role, Context (включая НФТ), Task (пошагово), Format.
- Новый артефакт: Summary, Risk Register (ID, Severity, file:line, Evidence, Rule, Repro, Mitigation), NFR Impact, Test Plan, Open Questions.
- Покрыты ключевые риски: 422/валидация, prompt injection, таймауты/5xx.

Замечания
- Evidence R2 содержит опечатку: строка с prompt обрывается без закрывающей кавычки: `prompt = f"Review this pull request and find problems:\n{diff}`.
- Нет явного раздела «Что отклонили».
- В журнале экспериментов не заполнены поля.

### 3) few_shot/experiment.md
Сильные стороны
- Хорошо сконструированный few-shot промпт: фиксированный формат ответа (Summary + ≤3 риска с file:line, evidence, rule, check).
- Эталонные примеры покрывают валидацию, prompt injection и таймауты.
- Новый артефакт соответствует формату, есть residual risks.

Замечания
- В примерах используются абстрактные пути `app/service.py:+NN` (для согласованности можно использовать реальные `app/review_service.py`).
- Нет явного раздела «Что отклонили».
- В журнале не заполнены поля.

### 4) tree_of_thoughts/experiment.md
Сильные стороны
- Три альтернативы (минимальный sync, async с неблокирующим LLM, очередь/фон), сравнительная матрица, аргументация выбора.
- Финальная реализация: Pydantic-модели, безопасный конструктор промпта, async LLM-обёртка с таймаутом, сервисный слой и FastAPI endpoint с DI.

Замечания
- Нумерация: дважды «## 3.» — раздел «Финальный артефакт» должен быть «## 4.».
- Fallback при парсинге JSON возвращает raw в `comment` без явного логирования/маркировки; допустимо для MVP, но стоит оговорить логирование.
- Нет раздела «Что отклонили» (например, откладывание очереди/фоновой архитектуры).
- В журнале поля не заполнены.

### 5) chain_of_verification/experiment.md
Сильные стороны
- Полный CoV: baseline, проверочные вопросы, независимые ответы, финальный артефакт (summary, топ‑3 риска с evidence/rule/check/mitigation, residual risks, test plan).
- Чёткая привязка к diff, отсутствие неподтверждённых тезисов.

Замечания
- Нет явно сформулированного раздела «Что отклонили».
- В журнале не заполнены поля.

### 6) react/experiment.md
Сильные стороны
- Нет.

Замечания (Critical)
- Файл фактически пуст: отсутствуют цель, входы, разрешённые/запрещённые действия, запрос, шаги, наблюдения и решения. Эксперимент ReAct не выполнен.

  - Техническая опечатка: Evidence R2.

- Tree of Thoughts

  - Что отклонили: отсутствует.

  - Что отклонили: отсутствует.

## Итоговая оценка по техникам
- Лучшее использование стандартов и источников: RAG.
- Лучшая структурная подача для командного принятия решений: RCTF.
- Лучшая инженерная архитектурная проработка: ToT.
- Лучшая проверочность выводов: CoV.
- Лучшая компактность/читабельность: Few-shot.
- Пробел: ReAct не реализован.

1) Быстрые правки качества

3) Заполнить practices/practice_02/prompts.md (журнал)
- Для каждой техники указать: «Изменённый файл Практики 1» (например, app/api.py, app/review_service.py), «Конкретное изменение» (валидация/422, response_model, безопасный промпт, таймауты/5xx), «Проверка» (из артефактов), «Что отклонили» (из добавленных разделов).
