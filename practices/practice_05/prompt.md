review-console — веб-консоль ревью diff + история ревью. Фича маленькая, но имеет и UI, и логику, и общий контракт:

Что видит пользователь (зона Команды 1, UI):

Одна страница ui/index.html + ui/app.js + ui/state.js (чистая логика состояний/редьюсер, тестируется в Node без браузера) + ui/api.js (клиент API на fetch, fetch внедряется параметром для тестов).
Поле для diff, живой счётчик строк/символов с лимитами, подсветка превышения; кнопка «Проверить» неактивна при пустом/слишком большом вводе; Ctrl+Enter = отправка.
Состояния экрана (явный конечный автомат): idle, loading, success, validation_error, llm_unavailable (с кнопкой «Повторить»), network_error; пустая история — отдельное пустое состояние; aria-live для статусов.
Панель «Последние ревью» (последние 5), клик показывает сохранённый результат.

Что делает система (зона Команды 2, логика):

app/api.py (+ app/server.py, запуск python -m app.server --port 8000) на stdlib http.server/ThreadingHTTPServer; раздаёт UI на / и API:
GET /api/limits → лимиты;
POST /api/reviews { "diff": "..." } → создаёт ревью через существующий ReviewService.review_code (его логику НЕ дублировать и НЕ менять поведением);
GET /api/reviews?limit=N → история, новые первыми;
GET /api/reviews/{id} → одно ревью.
app/history.py — потокобезопасное ограниченное хранилище (кольцо на 50), id и время создаются здесь.
Типизированные исключения DiffEmptyError(ValueError) и DiffTooLargeError(ValueError) в app/reviewer.py с ТЕМИ ЖЕ текстами сообщений, чтобы старые тесты прошли без изменений и API мог отдавать машинные коды ошибок.
Таймаут LLM → HTTP 504 с кодом LLM_UNAVAILABLE; валидация → 422; несуществующий id → 404; кривой JSON/нет поля → 400. Сервер — единственный источник истины по лимитам.

Ты вправе уточнить детали, но не расширяй границы: без БД, без аутентификации, без сторонних зависимостей.
